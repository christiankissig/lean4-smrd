# Summary

Lean4 Formalisation of Symbolic Modular Relaxed Dependencies per 
["Symbolic MRD: Dynamic Memory, Undefined Behaviour, and Extrinsic Choice" by Jay Richards, Daniel Wright, Simon Cooksey, Mark Batty](https://2025.splashcon.org/details/OOPSLA/104/Symbolic-MRD-Dynamic-Memory-Undefined-Behaviour-and-Extrinsic-Choice).

The definitions follow the restatement of SMRD in Appendix A of *Episodic Loops*.

# Differential testing against MoRDor

`smrd-es` runs the event structure semantics `denote` on a program given as JSON and prints the
event structure as JSON (see the header of `EsExport.lean` for both formats):

```bash
lake build smrd-es
.lake/build/bin/smrd-es program.json 2      # per-loop step-counter 2
```

`scripts/es_diff.py` compares it with [MoRDor](../mordor) on MoRDor's litmus tests. It takes each
program from `mordor parse --output-mode isa` and translates it to `smrd-es`'s input. It takes
MoRDor's event structure from `mordor interpret --output-mode json`. It then compares the two
program-order forests up to the renaming of event ids and symbols:

```bash
python3 scripts/es_diff.py --bound 2 ../mordor/litmus-tests ../mordor/programs/episodicity
```

It needs a MoRDor build (`dune build` in `../mordor`, or `--mordor PATH`). Each test comes out as
`agree`, `equiv` (expressions differ only syntactically), `pruned` (agree once events MoRDor does
not generate are dropped: those on an unsatisfiable path, and branches the path decides),
`value` (an expression is not equivalent), `differ`, `branches` (agree on every event but the
branch events, which MoRDor elides where the path decides them, unevenly), `cut` (see below),
`ub-model` (a difference under one of MoRDor's
UB-optimising models, `UB11`, `RC11UB` or `IMMUB`, which fold `e / !r` to `e` and `denote` does not),
or `skip` (a construct this library's syntax
lacks: non-atomics, locks, strong RMWs, RMWs on pointers, statements after a parallel block).
Registers read before they are assigned are unknowns in MoRDor, and `smrd-es` starts each of them
out holding a symbol of its own.

Loops are bounded differently. When a loop's counter runs out, `denote` generates nothing
(`⟨while b P⟩ ≜ ∅`, as in the paper), and that path ends. MoRDor instead generates one more loop
head (its `Blocked` check) and leaves the loop on its exit outcome. MoRDor's bound n is therefore
`denote`'s bound n + 1 with each loop's last body removed, and the test compares loop programs in
that form (status `cut`). `do B while c` is translated as `B; while c B`.

## Executions against the axioms

`smrd-ax` decides the axioms of executions given by finite relations (see the header of
`AxExport.lean`): No-Thin-Air, the coherence order, `CoherenceT`, RC11's `Coherence`,
`CoherenceV`, `CoherenceP` and Atomicity. `Smrd.AxiomEval` proves each decision equal to the
axiom of `Smrd.Executions`, `Smrd.CoherenceRC11` or `Smrd.CoherenceT`, for an execution whose
primitives (`⊑` within `X ∪ X_F`, `rf`, `rmw`, same location, `DP ∪ ≼`, the event classes and
`†`) the lists are.

`scripts/exec_diff.py` checks every execution MoRDor exports (`mordor executions`) against them,
with MoRDor's own `dp`, `ppo`, `rf`, `rmw` and `co` as the primitives:

```bash
lake build smrd-ax
python3 scripts/exec_diff.py -j 8 ../mordor/litmus-tests
```

It checks soundness only: that each execution MoRDor admits satisfies the axioms, not that
MoRDor finds them all. MoRDor's executions hold `X ∖ †`, and are checked as the transformed
executions they are. Executions are enumerated under sMRD whatever model a test names
(`--own-model` keeps the test's). Tests with non-atomic accesses or locks are skipped. See the
script's header for the translation, and for the diagnostic `DP ∪ ≼ ⊄ ⊑`.

## Finiteness and decidability of the elaboration closure

`Smrd.ElabDec` shows when the justifications generated by the elaborations (`Generated`) are
finitely many up to equivalence, and decidable for a finite event structure (a bounded
unravelling of a program), relative to a decision oracle for bounded arithmetic (`Oracle`:
satisfiability of bounded predicates, Büchi arithmetic, taken as given). The closure studied is
`GenR`: `Generated` with Strengthening conjoining predicates from a finite list `Qs` (MoRDor's
equations `val(e₁) = val(e₂)`, `mordorQs`) and, for decidability, without Weakening.

* `GenR.finite`, `GenR.bound`: a finite list of justifications represents the closure up to
  `JEq` (propositionally equivalent predicates, same dependencies, forwarding context and
  write), with a computable bound on pairwise inequivalent ones, given only that event values
  are not headed by a connective.
* `decideJ_iff`: under `Bounded` (locations, values, guards and RMW conditions in bounded
  arithmetic; no relaxed write writes a numeral that multiplies or divides), saturating `step`
  decides membership up to `JEq`. The bound is astronomically large; the procedure witnesses
  decidability and is not meant to be run.
* `Smrd.ElabDec.Examples`: the conditions hold of the library's litmus tests and of RCU's retry
  loop unravelled up to twice.
